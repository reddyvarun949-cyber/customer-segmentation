# Data dictionary — orders.csv and customers.csv

Synthetic data for a fictional online grocery store ("FreshCart") in six Indian cities, generated by
`generate_data.py` (seed 42). Orders cover calendar year 2025. Licence: created for this course; free to use and share.

There is **no target column**. This is an unsupervised (clustering) project: the segments are discovered in the notebook.

## orders.csv — one row per order (30,273 rows, 2,500 customers)

| Column | Type | Description | Values / range | Messiness added on purpose |
|---|---|---|---|---|
| `order_id` | text | Order identifier, numbered in date order | O100000 … | 150 rows are exact duplicates (same order exported twice) |
| `customer_id` | text | Customer who placed the order; links to `customers.csv` | C00001 … C02540 | none |
| `order_date` | date | Order date | 2025-01-01 to 2025-12-31 | none |
| `order_value` | number | Amount paid in rupees (₹) | about ₹100 – ₹8,500 | 60 missing; 47 refunds/cancellations recorded as 0 or a negative value |
| `items` | integer | Number of items in the basket | 1 – 87 | none |
| `category` | category | Main category of the basket | Fruits & Vegetables, Dairy & Bakery, Staples, Snacks & Beverages, Household, Personal Care, Meat & Seafood | none |
| `used_coupon` | 0 / 1 | 1 if a discount coupon was used | 0, 1 | none |
| `channel` | category | Where the order was placed | `app`, `web` | 400 rows written inconsistently (`App`, `APP`, `Web`, `WEB`, `" web"`) |

## customers.csv — one row per registered customer (2,540 rows)

| Column | Type | Description | Values / range | Missing |
|---|---|---|---|---|
| `customer_id` | text | Customer identifier | C00001 – C02540 | none |
| `age` | number | Age in years | 18 – 74 | 120 rows |
| `city` | category | City | Bengaluru, Mumbai, Delhi, Hyderabad, Pune, Chennai | none |
| `signup_date` | date | Date the account was created (always on or before the first order) | 2021-01 to 2025-11 | none |

40 customers in this table **never placed an order** in 2025, so they have no behaviour to cluster.

## Engineered customer features (built in the notebook, one row per customer)

| Feature | Formula | Meaning |
|---|---|---|
| `recency_days` | days from last order to 2026-01-01 | small = shopped recently |
| `frequency` | number of distinct orders | how often they shop |
| `monetary` | sum of `order_value` (₹) | total spend |
| `avg_basket` | `monetary / frequency` | typical order size |
| `coupon_rate` | mean of `used_coupon` (0–1) | price sensitivity |
| `app_share` | share of orders with `channel == "app"` (0–1) | preferred channel |
| `category_variety` | number of distinct `category` values (1–7) | breadth of shopping |

These are the 7 inputs of `POST /api/segment`.

## How the data was generated

Each customer is secretly given one of five shopping styles (frequent big-basket shopper, regular, deal seeker,
occasional shopper, lapsed shopper). The style sets the typical number of orders, basket size, coupon use, app use,
number of categories and — for lapsed shoppers — an early date after which they stop ordering. Every customer also
gets personal random variation, and every order gets its own random value, so styles overlap.

The hidden style is **not** saved. The segments found in the notebook are a data-driven interpretation, not a
recovery of "true labels" — exactly as in a real project. Age and city are generated independently of the style.
